## A. Page safety (review §2, "the page commands, Claude obeys")

**A1 · Site scope per chat** (S1a)
- Now: page tools act on any http(s) tab; only Google sign-in and non-web schemes are blocked (extension/lib/policy.js:30-55; Unsafe skips the checks at :44). Calls go through extension/background.js:1074 and the gates in extension/lib/tools.js (cizGateOpts :769, cizGatedTab :787, cizPageTab :800, cizRefuseUrl :868). The current tab is only a prompt line (host :745-748), taken from the last focused window (background.js:690).
- 0.11: each chat keeps a site list (a site covers its subdomains), seeded with the current tab's site, sites named in the message, @tabs and the context-menu page. A tool on any other site, or navigate/tab_open to one, shows a chat card: Allow this message / Allow this chat / Deny. No answer in 2 minutes counts as Deny. Built on the watch card's gate pattern (host/lib/watchgate.js, panel #watchCard).
- Pins / risk: no test pins it. With the panel closed the card cannot show, so the call is refused.

**A2 · Confirm risky actions after a page read** (S1b)
- Now: nothing tracks page reads (PAGE_CONTENT, host/lib/tools.js:329; results reach the helper at host :130-143).
- 0.11: once a message has read page content, a POST form submit (a click on a submit control, Enter in a form) or a navigation to another site asks once (Allow / Deny). GET forms such as searches, inside the site list, do not ask. The click and key operations classify the target first (a new page-side check).
- Pins / risk: a script-driven POST without a form cannot be seen; the spec says so.

**A3 · WebFetch only inside the site list** (S1c)
- Now: WebSearch and WebFetch are always allowed (host/lib/chatargs.js:24, :177 --allowedTools, :180 --tools); no domain rule anywhere.
- 0.11: WebFetch works only for sites in the chat's list, checked by a PreToolUse hook in the chat settings that asks the helper, so the list can grow mid-chat. After a message reads a local file or local page, WebFetch is off for the rest of that message. WebSearch stays.
- Pins / risk: hook behavior in `claude -p` with `--settings` is unverified on F's CLI (live check). Fallback: WebFetch off by default with a Settings switch.

**A4 · tabs_list** (S1d)
- Now: every tab in every window, with title and full URL (extension/lib/tools.js:934-941).
- 0.11: the chat's own window only; tabs outside the site list show id and site only (no title, path or query).

**A5 · Trusted mode** (S1e)
- Now: none. Unsafe mode is the pattern to copy (panel.html:208-211 → background.js:558-572 → host :763-768 and :639).
- 0.11: a Settings switch, off by default, for the session only, turned on through the confirm window. It lifts A1 to A4; the site list's Block (A7) still holds.

**A6 · Prompt lines** (S1f)
- Now: "there is no confirmation step" (chatargs.js:78, zen-mcp.js:56).
- 0.11: the prompt explains the cards and tells Claude to stop and say so when a site is refused.
- Pins / risk: host/test/chat-smoke.js:220 ("chat prompt has no ask-before rule") changes with this spec.

**A7 · Per-site list: allow, ask, block** (review feature 4)
- Now: only the built-in BLOCKED_HOSTS (policy.js:16-24).
- 0.11: Profile → Permissions → Sites, saved in storage.local. Allow puts a site in every chat's list; Block refuses every tool there, even in Unsafe and Trusted.

**A8 · Army workers** (S15)
- Now: workers may act on any http(s) site except Google sign-in (tools.js:764-767; host/lib/armyguard.js:7-48).
- 0.11: workers get the lead's site list at army_start and never ask; calls outside it and A2 actions are refused with a message for the lead.

**A9 · network_log behind the page gate** (S13)
- Now: network_log uses cizTabFor instead of the page gate (tools.js:1064-1066).
- 0.11: the same gate as the other read tools, plus A1.

**A10 · new: sensitive fields in Portuguese**
- Now: password, 2FA and payment detection matches English words only (policy.js:137-142), so "Senha", "Número do cartão" or "Código de verificação" get through unless the field is type=password.
- 0.11: add Portuguese and Spanish terms, with checks for each.

## B. Files, local pages and the helper (review §2)

**B1 · Broad folders and deny rules** (S2)
- Now: folderProblem (host/lib/guard.js:94-104) accepts the home folder, %APPDATA% and %LOCALAPPDATA%. Protected places get a Read deny only (:76), Claudefox's own files an Edit deny (:80). Chat turns pass no --setting-sources.
- 0.11: refuse drive roots, the home folder, %APPDATA%, %LOCALAPPDATA% and any parent of the data folder, for file tools and local pages. Add Edit and Write denies next to every Read deny, plus the whole data folder, the Startup folder and the PowerShell profile folders. Pass `--setting-sources user` on chat turns. The confirm text names what stays off limits.
- Pins / risk: Claude Code's Edit/Write deny semantics are unverified (guard.js:4-5 assumes a Read deny covers them).

**B2 · Secret paths** (S11)
- Now: browser profiles, Windows credentials, ~/.ssh, cloud CLIs, password managers and key files are covered (guard.js:15-43).
- 0.11: add Discord, Slack and Telegram Desktop token folders, GitHub CLI hosts.yml, PSReadLine history, VS Code globalStorage, *.key, *.ovpn and wallet.dat.

**B3 · Local page grants** (S3)
- Now: grants are saved forever in local-grants.json (host/lib/localpages.js:100-111), and the confirm does not say what Claude was reading.
- 0.11: grants last for the session only (old saved grants are dropped once, with a log line). The confirm shows the site Claude was reading. B1's refusals apply, and A3 turns WebFetch off after a local read.

**B4 · Folder picker asks again** (S7)
- Now: a folder picked in the Windows picker replaces the grant without asking (host :112).
- 0.11: the confirm window asks for the new folder; No keeps the old one.

**B5 · Unsafe out of sync after a helper restart** (S8)
- Now: the add-on keeps showing Unsafe and file tools on while the helper has silently dropped them (background.js:880-887; host :639).
- 0.11: the helper sends its confirmed state on hello and after each change, and the add-on mirrors it.

**B6 · Improve** (S4, part of S10)
- Now: --permission-mode acceptEdits with unscoped Edit and Write (host/lib/selfimprove.js:378-380); the test run is stopped with child.kill (:401); the friends zip has no tests, so Improve never passes there.
- 0.11: Edit and Write only inside the sandbox's extension/mods/; --permission-mode dontAsk; tests run in a clean copy plus the mod's files; tree kill (killTree, host/lib/army.js:21-35); the friends zip carries test/ and host/test/.

**B7 · Remote MCP servers ask first** (S5)
- Now: https servers are added with no confirm (host/lib/toolbox.js:560-571); only command servers ask (:584-589).
- 0.11: the confirm window for remote servers too, showing name and URL, never header values.

**B8 · Confirm window text and cmd** (S6)
- Now: raw text with no height cap (host/confirm.ps1:38-40); `cmd /c` before npx lets `&&` in arguments run in cmd (toolbox.js:573-586).
- 0.11: a monospace box with a height cap and scroll, whitespace collapsed; the window shows the exact argument list that runs; `& | < > ^ %` and line breaks are refused when cmd /c is used.

**B9 · Test hooks in release builds** (S9)
- Now: the CONFIRM, PICK, CLAUDE, ZEN_EXE, PIPE and SCRIPT overrides are read in every build (confirm.js:27, host :101, :414, localpages.js:59, paths.js:24, zen-mcp.js:101); the seven ARMY_* limits accept any value (armyguard.js:13-19).
- 0.11: the overrides work only with the test flag set; ARMY_* values can only lower the limits.
- Pins / risk: every test that uses a hook sets the flag.

**B10 · Orphan processes** (S10)
- Now: nothing cleans up when the helper starts; on Linux the chat child is not in its own process group.
- 0.11: the helper records child process ids in the data folder and kills the recorded trees at start (checking the image name first); children spawn in their own group.

**B11 · Native message size** (S12)
- Now: input has no limit (host/lib/nm.js:14, :36); output over 1 MB throws, and the add-on is not told (:53).
- 0.11: inputs over 64 MB are drained and refused with an error to the add-on; an oversized output becomes a short error message.

**B12 · Output folder out of the extension** (S16)
- Now: saved files go to extension/output inside the source tree (host :73).
- 0.11: the data folder's output\ (moved once), and the add-on opens the new place.

**B13 · new: model allowlist**
- Now: `MODELS[msg.model]` accepts any key (host :637), so a message naming "selfimprove" runs Opus at max effort in a normal chat.
- 0.11: only speed, speedplus, quality and army are accepted.

## C. Cost and speed (review §3)

**C1 · Army lead effort** (Top 10 #1)

- 0.11: 12,000 for workers; a `query` argument for every caller returns only the matching blocks with their headings; workers use find or analyze_page first.

**C5 · Compact JSON** (Top 10 #5)

- 0.11: no indentation.

**C6 · Worker effort** (P5)
- Now: Haiku at high (chatargs.js:22).

**C7 · Server instructions** (P6)
- Now: about 300 words of server instructions repeat the system prompt (zen-mcp.js:39-58).

**C8 · One claude process per chat** (P8)
- Now: one `claude -p` per message (host :661); argv from chatargs.js:166-187; a turn ends when the process exits.

It respawns with --resume when model, effort, caveman, Unsafe, Trusted, file tools, plugins or account change, after Cancel, and after 10 idle minutes. **C9 · Plugin scan in the background** (P9)

**C10 · Tool server reconnect** (P10)
- Now: no retry (zen-mcp.js:67-126).
- 0.11: one retry after 300 ms, only when the call was never sent.

**C11 · Cost and tokens shown** (P17)
- Now: only time and turns reach the panel (host :583-589); workers drop their usage.
- 0.11: tokens (in, out, cache read) and "≈ $ at API prices" on the done line and in army_wait results; the army's day counter adds tokens.
- Pins / risk: test/dom-panel.js:142 ("Done in 4.2 s") keeps its prefix.

**C12 · Streaming render** (P11)

- 0.11: a version number per message; markdown re-rendered at most every 150 ms while streaming; saves wait for a pause.

**C13 · Page text cache** (P12)
- Now: each get_page_text part rebuilds the markdown from the top (tools.js:466-474).
- 0.11: cached per document in window.__cizSt, keyed by URL and a cheap DOM signature, for 60 s.

**C14 · Inject once per document** (P13)

**C15 · Screenshot** (P14)

- 0.11: JPEG at quality 80 and scale 1; an optional scale 0.5, with a note to double click coordinates.

**C16 · Network log only while running** (P15)

**C17 · Tool results matched by id** (P16)
