# Claudefox 0.11: build plan (army)

Spec: `docs/superpowers/specs/2026-10-11-claudefox-0.11-design.md` (approved by F, 12 Oct). Item IDs come from it.

## How it runs (F, 12 Oct)
- Commander: Opus 5.5 (this session). It plans each wave, briefs the workers, re-runs every gate, reviews the diffs and commits.
- Workers: 4 × Haiku 5.5 at max effort, with no sub-agents. Each worker has its own clone at `$HOME/army/w1..w4` on the device VM's local disk and its own branch, `army/<task>`, cut from `dev`.
- A worker writes the test first, makes it pass, runs the full suite in its clone (`NODE_PATH=$HOME/jsd/node_modules node test/run-all.js`), and commits on its branch with no trailers.
- The commander cherry-picks each verified commit into F's `dev`, as F-F-Bukharin, one task per commit. F's folder only ever receives verified commits.
- Rollback point: branch `agent-army/checkpoint-0.11-start` (`3d3c57c`). Baseline: 24 test files green, 38 s in a local clone.
- Within a wave, no two workers own the same file. Shared files (manifest.json, test/run-all.js) are merged by the commander.
- A worker that fails its gates twice gets the task again with a fresh brief. Escalation to Sonnet only with F's OK.

## Waves
1. Code shape (D4, D2, D1). W1: the helper renames, the shared modules and the main-file split. W2: panel.js split. W3: background.js split. W4: pageTools.js rename and the cizPageOp split.
2. Hardening (B1 to B13, U1, A10), owned by file area.
3. Page safety (A1 to A9): the add-on gate and the card, the taint classifier, the WebFetch hook with the helper's scope, and Trusted mode with tabs_list and the prompts.
4. Cost and speed (C1 to C17).
5. Panel and features (U4, U5, E1 to E3, E6 to E10, E12 to E14, U2).
6. Portuguese (E11).
7. Rename and release (D3, E5), the watch skill, a clean-export full run, then F's live checks.

Each wave's briefs are written when the previous wave has merged, from its diff and from the review map.
